# 40-BACKEND — каркас ядра Posiz

FastAPI + PostgreSQL + Redis. Это **скелет**: контракт, схема, адаптеры, комплаенс и «рой» на месте,
реальные OAuth-интеграции и LLM подключаются на следующем шаге (точки помечены `TODO(llm)` / `dry_run`).

## Запуск

```bash
cp .env.example .env
docker compose up --build           # api :8000, worker, postgres, redis
# локально:
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
PYTHONPATH=src uvicorn orbita.main:app --reload --host 0.0.0.0 --port 8000
```

- Swagger: http://localhost:8000/docs
- Health: http://localhost:8000/health
- Тесты: `PYTHONPATH=src pytest -q`

Режим `DRY_RUN=true` (по умолчанию) — адаптеры не обращаются к реальным API, возвращают фиктивные id.
Это позволяет прогонять весь пайплайн без токенов.

## Медиа: карточки и обложки (этап A медиа-конвейера)

Первый шаг к роликам из `00-STRATEGY/11-video-engine.md`: **статические форматы**. Пост
превращается в карточку 1:1, 9:16 или 16:9 без браузера, без внешних сервисов и без
сгенерированного кода — вёрстку задаёт закрытая библиотека шаблонов, модель заполняет только
данные. Решение и границы — `10-ARCHITECTURE/adr/0023-media-reels-engine.md`.

```http
GET  /api/v1/media/templates          библиотека шаблонов и лимиты (что можно выбрать)
POST /api/v1/media/specs/validate     сухая проверка спеки: без записи и рендера
POST /api/v1/media/cards              пост → карточки в 1–3 форматах (201; 422 если не собрался ни один)
GET  /api/v1/media/jobs[?limit=]      задачи рендера + сводка
GET  /api/v1/media/jobs/{id}          задача и её спека
POST /api/v1/media/jobs/{id}/cancel   отмена
GET  /api/v1/media/assets/{id}        готовый артефакт (`image/svg+xml`)
GET  /api/v1/media/assets/{id}.png    то же в PNG (`?format=png`; 409 raster_unavailable, если растра нет)
GET  /api/v1/media/public/{token}     картинка по подписанной ссылке — БЕЗ авторизации, живёт час
POST /api/v1/media/purge?ttl_days=14  уборка артефактов по TTL (то же делает воркер по cron)
```

Что проверяется **до** рендера (всё — арифметика, не «модель посмотрела»):

| Проверка | Порог | Что ловит |
| --- | --- | --- |
| схема спеки | `reel.spec.v1`, 4 шаблона, 3 формата | выдуманный шаблон, чужая версия, лишние поля |
| длина текста | заголовок ≤ 90, пункт ≤ 48, титры ≤ 42 знака | «простыню», которую никто не прочитает на телефоне |
| обрезка | bbox каждого блока внутри кадра | текст, выехавший за край |
| safe zone | 9:16 — 860 × 1280 при отступах 220/420/80/140 | текст под кнопками клипов и Shorts |
| контраст | ≥ 4.5:1 для каждой пары «текст/подложка» | бренд-цвета, на которых текст не читается |
| маркировка | `ad: true` → `erid` + рекламодатель + ИНН | рекламу без маркировки: рендер отвергается |

Ширина текста считается **по замеренным метрикам глифов** (158 символов, `canvas.measureText`
в Chromium, отдельно для начертаний 400 и 800): первая версия оценивала кириллицу в 0,52 em и
пропускала обрезанные заголовки — теперь расхождение в пределах нескольких пикселей.

Детерминизм и стоимость: одинаковый вход (спека + версия рендерера `inhouse-svg@1`) даёт
побайтово тот же SVG, `spec_hash` отдаёт готовый артефакт вместо повторного рендера. Спеки,
задачи и артефакты живут в `entity_docs` (коллекции `reel_specs`, `render_jobs`, `media_assets`) —
это тот же strangler-слой, что у остальных доменов v3.

Тесты этапа A: `tests/test_media_cards.py` — 38 проверок (схема, геометрия, контраст, комплаенс,
детерминизм, идемпотентность, экранирование текста, изоляция задач по workspace, API).

## Медиа: растр, хранилище и публичные ссылки (этап B)

Этап A отдавал SVG: он диффится в тестах, но мобильные клиенты VK/Telegram/MAX его не
растеризуют или растеризуют частично. Этап B добавляет три недостающих звена — **PNG**,
**хранилище вне процесса** и **ссылку, которую может скачать канал**.

**Растр** (`media_raster.py`). Порядок выбора движка: `MEDIA_RASTER_BIN` → `rsvg-convert` →
Chromium → ImageMagick. Chromium ищется и в `PATH`, и в кеше playwright
(`~/.cache/ms-playwright/chromium-*/…`), потому что в CI и на «тонком» образе его там больше
всего шансов найти. ImageMagick идёт последним и помечается как низкая точность: без делегата
`librsvg` он подменяет шрифт на serif и теряет градиенты — на карточке это видно сразу.
Если бинарь нашёлся, но не запускается (нет системных библиотек), `available()` честно пишет
причину, а переменная `MEDIA_CHROME_LIBS` позволяет передать каталоги библиотек
(`LD_LIBRARY_PATH` только у дочернего процесса).

**Хранилище** (`media_storage.py`). Ключи `media/<workspace>/<asset_id>.svg|.png` строит только
код, и всё равно они проверяются: артефакт отдаётся по HTTP, и `../` в ключе означал бы чтение
файлов сервера. Запись атомарная (`os.replace`), поэтому API и воркер могут смотреть в один
каталог. Режимы — спул (`MEDIA_STORAGE=spool`, по умолчанию) и S3/MinIO (`MEDIA_STORAGE=s3`):
второй без `boto3` не притворяется, что сохранил — поднимается `StorageError` и API отвечает
ошибкой, а не «ок».

**Публичные ссылки.** Telegram тянет картинку сам, без наших заголовков, поэтому ссылка
подписана: `base64url(id:формат:срок:HMAC-SHA256)`, живёт час, даёт доступ ровно к одному
артефакту. Подделка и просрочка — `403`. Секрет — `MEDIA_URL_SECRET` (или `JWT_SECRET`);
без него ссылки не выдаются вовсе (это видно в гейте, а не в проде).

**Вложения в публикации.** `POST /publications` принимает `media_ids` (до 10, дубли
схлопываются). Существование артефактов проверяется **при создании** (409
`media_asset_unknown`), а ссылки собираются **в момент отправки** в воркере: пост может висеть
в очереди сутки, а ссылка живёт час. Если ссылку собрать нельзя (нет секрета, артефакт удалён
по TTL), публикация не уходит без картинки молча — это отдельный класс ошибки
`media_unavailable`, а не «transient» с бессмысленными ретраями.

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `MEDIA_STORAGE` | `spool` | `spool` — каталог, `s3` — S3/MinIO |
| `MEDIA_SPOOL_DIR` | `var/media` | корень спула (общий том API и воркера) |
| `MEDIA_S3_BUCKET` / `MEDIA_S3_ENDPOINT` / `MEDIA_S3_REGION` | — | бакет и MinIO-эндпоинт |
| `MEDIA_RASTER_BIN` | автопоиск | явный путь к rsvg/Chromium (в проде предсказуемее) |
| `MEDIA_CHROME_LIBS` | — | каталоги библиотек для Chromium (через `:`) |
| `MEDIA_URL_SECRET` | `JWT_SECRET` | подпись публичных ссылок |
| `MEDIA_PUBLIC_BASE` | `SITE_URL` | внешний адрес API для ссылок |
| `MEDIA_TTL_DAYS` | `14` | срок жизни артефактов, уборка — cron воркера в 04:20 |

Тесты этапа B: `tests/test_media_storage.py` — 31 проверка (ключи и выход за корень, атомарность,
TTL, режим S3 без `boto3`, IHDR/растр, подпись/просрочка/подделка токена, PNG-эндпоинт,
публичная ссылка без авторизации, `media_ids` в публикации).

В release gate медиа занимает **20 пунктов из 47** — от схемы спеки до плашки маркировки в
кадре (актуальный перечень ведётся в `../10-ARCHITECTURE/adr/0023-media-reels-engine.md`).

## Медиа: ролики 9:16 из поста (этап C)

Карточка — статика, ролик — **время**: сцены, длительности, прогресс-бар и титры, которые
меняются каждые 200–400 мс. Поэтому отдельные модули `media_reel.py` (спека, таймлайн, кадры) и
`media_video.py` (FFmpeg).

**Кадр — чистая функция от времени.** `frame_at(spec, t)` без состояния: тот же `t` даёт
побайтово тот же SVG. Из этого следует всё остальное — кадры рендерятся параллельно, один
дефектный участок переснимается без пересборки ролика, а тест сравнивает два рендера.

**Сцены — закрытая библиотека.** `hook-typed` (заголовок печатается посимвольно),
`chips-flow` (пункты появляются по одному), `captions-stack` (слово подсвечивается по
таймингу), `cta-card` (финал). Модель выбирает сцену и заполняет текст — вёрстку и анимацию
задаёт код, поэтому бренд-консистентность проверяется тестом, а не «на глаз».

**Длительность считается по тексту**, а не «по 5 секунд на сцену»: сцена держится столько,
сколько нужно, чтобы её прочитали (2,6 слова/с), с минимумами на сцену. Итог ограничен 60 с,
кадры считаются **по сценам** — `round(10,34 × 30) = 310`, а сумма покадровых округлений 311;
ролик, собранный по общей длительности, теряет кадр на стыке сцен и уводит титры.

**Растр в кадре.** 300–900 кадров CLI-запуском Chromium — это полчаса (по ~3 с на кадр из-за
`--virtual-time-budget`). Поэтому есть пакетный путь `media_raster.rasterize_many`: один браузер
и `page.screenshot()` на кадр (~50 мс), а пофреймовый остаётся запасным. Playwright —
необязательная зависимость: без него ролик всё равно соберётся, просто медленнее.

**FFmpeg проверяется, а не «собрался».** `probe_bytes` читает `moov`/`mvhd`/`tkhd` из самого
файла (ffprobe может отсутствовать), поэтому всегда видно длительность, размеры и `faststart`.
Длительность выставляется явно (`-t`): без этого контейнер «дотягивал» 0,4-секундный тест до
0,999 с — поймано тестом, а не глазами. Битрейт считается от лимита канала (Telegram по URL —
20 МБ), а не «в максимум качества».

```http
GET  /api/v1/media/reels                  задачи роликов и сводка
POST /api/v1/media/reels                  пост или спека → ролик (201; render=false — только смета)
GET  /api/v1/media/reels/{id}             задача, спека, таймлайн, ключевые кадры
GET  /api/v1/media/reels/{id}.mp4         готовый MP4 (409 video_unavailable с причиной)
GET  /api/v1/media/reels/{id}.png         постер (кадр из готового видео)
GET  /api/v1/media/reels/{id}/frame?t=    кадр на любой секунде — SVG, без хранения 900 файлов
```

Вложения публикации принимают id ролика наравне с карточками: `media.best_format()` возвращает
`mp4`, ссылка подписывается так же (`/media/public/{token}`), воркер передаёт её в
`PublishInput.media_urls` — канал скачивает ролик без нашей авторизации.

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `MEDIA_FFMPEG_BIN` | автопоиск | путь к ffmpeg (в образе ставится явно) |
| `MEDIA_FFPROBE_BIN` | автопоиск | путь к ffprobe для точных метаданных |

Тесты этапа C: `tests/test_media_reels.py` — 35 проверок (спека и лимиты, таймлайн, детерминизм
кадра, подсветка титров, подбор кегля без обрезки, сборка MP4 и его проверки, честный отказ без
ffmpeg, API и публичная ссылка на ролик). Гейты: `media.reel_spec`, `media.reel_frames`,
`media.reel_encode`.

## Медиа: озвучка и синхрон (этап D)

Озвучка — единственная стадия, где ошибка **слышна**, а не видна. Поэтому `media_voice.py`
решает четыре задачи, а не «вызывает TTS».

**Произношение.** «38-ФЗ», «erid», «ОРД», «ИНН», «100%» уходят в синтез словами, а в кадр и в
субтитры — исходным написанием. Машинные идентификаторы (erid-хэши) вслух **не читаются**:
диктор, произносящий «два вэ тэ зэт кью», — это не маркировка, а издевательство.

**Смета до запроса.** Yandex SpeechKit: 1 342 ₽ за 1 млн знаков с НДС (API v1) — значит
600-знаковый ролик стоит ≈0,8 ₽. Цифра попадает в задачу ролика, как смета канала перед
публикацией.

**Синхрон.** Длительность ролика подстраивается под речь, а не наоборот: сцены масштабируются
пропорционально, но **минимумы сцен соблюдаются** (сцена на 0,8 с — это мигание), а тишину в
конце добирает `apad`. Титры получают тайминги слов от речи, поэтому подсветка совпадает с
голосом. Настоящее выравнивание (faster-whisper) — необязательная зависимость: без неё слова
раскладываются пропорционально длине по длительности аудио (±120 мс), с ней — берутся из
распознавания.

**Честность.** Без `YANDEX_TTS_API_KEY` провайдер `yandex` возвращает причину, а не тишину под
видом озвучки. Работают `mock` (тишина нужной длины — тесты и песочница) и `file` (готовая
озвучка диктора, демо) — путь кодирования тот же.

```http
POST /api/v1/media/reels               { ..., "voice": {"provider":"yandex","voice":"ermil","rate":1.0} }
GET  /api/v1/media/reels/{id}.mp3      озвучка ролика
GET  /api/v1/media/reels/{id}.srt      субтитры из тех же таймингов, что уходят в кадр
GET  /api/v1/media/summary             voice: {providers, yandex, alignment}
```

| Переменная | Зачем |
| --- | --- |
| `YANDEX_TTS_API_KEY` / `YANDEX_TTS_IAM_TOKEN` | ключ SpeechKit (рубли, без VPN) |
| `YANDEX_TTS_FOLDER_ID` | каталог Yandex Cloud для IAM-режима |

Тесты этапа D: `tests/test_media_voice.py` — 16 проверок (словарь произношения, смета, честный
отказ без ключа, монотонность таймингов, длинное слово дольше короткого, `.srt`, подгонка
таймлайна под речь с сохранением минимумов, аудио в MP4, публичная ссылка на `.mp3`). Гейты:
`media.voice_plan`, `media.voice_sync`.

## Медиа: комплаенс в кадре (этап E)

Плашка «Реклама» — не украшение, а условие выпуска: штраф за немаркированную рекламу — до
500 тыс. ₽. Поэтому маркировка сделана **правилом, которое блокирует рендер**, а не галочкой в
чек-листе.

**Правило — данные рынка.** `media_compliance.py` содержит пакеты: `ru-ad` (пометка «Реклама»,
рекламодатель, ИНН, `erid`), `ru-info` (реклама запрещена), `eu-disclosure` (`Ad` / `Anzeige`,
без `erid`), `us-ftc` (`Paid partnership`), `generic`. Новый рынок добавляется файлом
`MEDIA_COMPLIANCE_PACKS` — **без правки рендерера** (контракт гибкости,
`../00-STRATEGY/12-platform-flexibility.md`). Неизвестный пакет — ошибка, а не тихий откат на
умолчание.

**Нельзя выпустить немаркированное.** `ad: true` без `erid`/рекламодателя/ИНН → `422` с
кодами (`erid_required`, `advertiser_required`, `inn_invalid`), одинаково для карточки и ролика.
Прочерк вместо `erid` — тоже отказ (`erid_invalid`).

**Плашка действительно в кадре.** Текст плашек считает `plates()` из тех же данных, что уходят
в описание канала (`description()` → `GET /media/reels/{id}.txt`), поэтому «в кадре есть, в
описании нет» не разъезжается. Место под маркировку **резервируется заранее**: текст сцены
уезжает вверх, а не наезжает на плашку; возрастная метка уходит в угол. Плашка и прогресс-бар
живут **внутри зоны контента** — нижние 420 px закрывает интерфейс Shorts/клипов, и маркировка
под ними формально есть, фактически нет.

```http
GET  /api/v1/media/compliance/packs      пакеты правил: что требуется и чем рисуется
GET  /api/v1/media/reels/{id}.txt        маркировка для описания (из тех же данных, что плашка)
POST /api/v1/media/reels                 {..., "compliance": {"pack":"ru-ad","ad":true,"erid":"…",
                                          "advertiser":"ООО «…»","inn":"7700000000","min_age":18,
                                          "disclaimer":"Не является публичной офертой"}}
GET  /api/v1/media/summary               compliance: {default_pack, packs}
```

Тесты этапа E: `tests/test_media_compliance.py` — 28 проверок (пакеты и их требования, языки
пометки, возрастные категории по рынку, отказ на неизвестный пакет, `erid` без признака рекламы,
переполнение дисклеймера, порядок плашек, плашка на каждом кадре ролика, safe zone и резерв
места, артефакт `.txt`, API-отказы с кодами). Гейты: `media.compliance_packs`,
`media.compliance_block`, `media.compliance_safe_zone`.

## Медиа: гибкость вместо нишевых констант (P0)

Первый вариант движка был честным, но «однонишевым»: формат 9:16 зашит в рендерер, лимиты —
константы модуля, brand kit — три цвета, TTS — ветка `if`. Для платформы, которая обслуживает
магазин, клинику и агентство, это дефект: каждая новая ниша требовала бы релиза
(`../00-STRATEGY/12-platform-flexibility.md`).

**Формат — поле спеки.** `media.FORMATS` содержит 9:16, 4:5, 1:1 и 16:9; `canvas()` считает
масштаб типографики от высоты зоны контента (9:16 — база 1280 px), а переносы строк идут по
реальной ширине зоны. Один и тот же ролик выходит в ленту, Shorts и на YouTube — без отдельной
вёрстки; `media_video.checks` проверяет размеры того формата, который просили.

**Brand kit — данные клиента.** `theme` (`dark`/`light`), `font` (`sans`/`serif`/`mono`),
`scale` (0,8…1,3), цвета и `muted` — из спеки. Светлая тема меняет и палитру плашки: янтарный на
белом нечитаем. Неизвестные значения — ошибка валидации, а не тихая подмена.

**Лимиты — конфигурация.** `media_reel.limits()` читает `MEDIA_REEL_MAX_DURATION`,
`MAX_SCENES`, `MIN_DURATION`, `MAX_FRAMES` на каждый вызов: 60 секунд под Shorts сегодня,
180 — завтра, без релиза.

**Провайдеры озвучки — реестр.** `media_voice.PROVIDERS` хранит цену, языки, режим,
проверку доступности и обработчик. Новый TTS добавляется записью, а не веткой в синтезе;
`estimate_cost(chars, provider)` и витрина `available()` собираются из реестра. В задаче ролика
две цифры: `cost_rub` (чем реально синтезировали — в песочнице 0 ₽) и `cost_cloud_rub`
(во сколько обойдётся боевой провайдер).

```http
GET  /api/v1/media/templates    formats: [9x16, 4x5, 1x1, 16x9], brand: {themes, fonts, scale}, reels.limits
POST /api/v1/media/reels        {..., "format":"16x9", "brand":{"theme":"light","font":"serif","scale":1.1}}
```

Тесты: `tests/test_media_generality.py` — 28 проверок (четыре формата из одной спеки, масштаб

## v3.18: хук-лаборатория (этап F)

Досмотр решается в первых двух секундах, поэтому тестировать надо не ролик целиком, а хук.
`media_lab.py` строит **одну спеку в нескольких вариантах**: у них совпадают сцены, титры,
тайминги и длительность — различается только `headline` первой сцены. Поэтому разница в досмотре
относится к хуку, а не к ролику. Три «разных ролика» дали бы красивый отчёт и никакого вывода.

**Хук собирается из данных поста, а не из фантазии модели.** `media_lab.STRATEGIES` — реестр
стратегий (цифра из поста, число пунктов, вопрос к аудитории, прямой заголовок), у каждой поле
`needs` (`number`/`count`/`topic`/`title`). Нет данных — стратегия попадает в `skipped` с причиной,
а не выдумывает факт: «2 пункта» не появится там, где в посте один пункт, а вопрос не строится из
самого заголовка (иначе A/B превращается в сравнение двух одинаковых идей). Обещания результата
(«гарантируем», «точно вырастет») запрещены стоп-листом `compliance.py`, и лаборатория не
предлагает их даже как вариант: тест не может нарушать закон.

**Победитель — только по накопленным данным.** Метрики пишутся приращениями (`views`,
`completions`, `avg_watch_seconds`): аналитика канала отдаёт срез несколько раз, и «перезапись
последним значением» теряла бы историю. Метрика решения — `watch_ratio` (средний досмотр /
длительность), если аналитика его дала, иначе `completion_rate`; порог **100 показов** на
вариант; `gap ≤ 0,01` — честный `tie`; один прошедший порог вариант — `not_enough_data`
(«сравнивать не с чем»). Победитель фиксируется (`winner_variant_id`, `winner_spec_hash`,
`decided_at`), повторное решение возвращает его же, а ролик собирается по уже посчитанной спеке.

```http
POST /api/v1/media/hooks                    {post, count: 3}   → 201: варианты + skipped
GET  /api/v1/media/hooks                    список лабораторий
GET  /api/v1/media/hooks/{lab_id}           варианты, метрики, таблица и решение
POST /api/v1/media/hooks/{lab_id}/metrics   {variant_id, views, completions, avg_watch_seconds}
POST /api/v1/media/hooks/{lab_id}/decide    → победитель; 409 hook_not_decided без данных
POST /api/v1/media/reels?render=false       ролик по спеке победителя
```

Тесты: `tests/test_media_hook_lab.py` — 27 проверок (стратегии и слоты данных, отказ без данных,
склейка `skipped` без дублей, «варианты различаются только первым кадром», накопление метрик
приращениями, tie при равенстве, порог показов, идемпотентность `decide`, API 201/409/404/200).
Гейт: `media.hook_lab`. Демо — `scripts/demo_hook_lab.py`, результат —
`../20-DESIGN/video/backend/reel-hooks-storyboard.png` и `hook-lab-demo.json`.

## v3.19: recycle, языки и видео-отчёт (этап G)

Три вещи, которые в интерфейсе выглядят как кнопки, а в коде являются решениями о данных.

**Recycle: «топ-пост» — это число.** `media_recycle.candidates()` берёт опубликованные посты,
складывает снимки `store.METRICS` (аналитика приходит срезами) и считает вовлечённость
`(реакции + переходы) / показы`. Порог — 100 показов: без него «1 реакция из 1 показа» даёт 100 %
и побеждает кампанию с 5 200 показами. Посты без аналитики и ниже порога не исчезают из ответа — они
уходят в `skipped` с причиной (`no_metrics`, `below_threshold`), потому что вопрос «почему в списке
два поста, а не четыре» задают всегда.

В спеке ролика появляется блок `origin`: публикация, канал, показы, вовлечённость и человеческая
причина выбора. Он входит в `spec_hash`, поэтому recycle из разных постов — разные артефакты, а
повторный recycle того же поста возвращает тот же ролик.

**Язык — профиль данных, а не перевод строк.** `media_locale.LOCALES` хранит темп чтения, лимиты
строки и слова титров, тег голоса. Английский читается 3,1 слова/с против 2,6 у русского: та же
спека на `en` короче (13,0 → 11,0 с в демо), потому что тайминги считаются по профилю языка, а не
по русской константе. `media_reel.localize(spec, locale, texts)` принимает **переведённые строки**
и пересчитывает тайминги; если перевод не влезает в кадр — возвращается отказ с замечаниями и
исходная спека, а не «перевели и обрезали». Неизвестный язык — `locale_unknown`, а не тихий откат
на русский.

**Видео-отчёт агентства — те же цифры, что в кабинете.** `media_report.build()` считает охваты,
реакции, переходы, вовлечённость и топ-посты из `store`, собирает ролик тем же движком и кладёт
рядом блок `sources`: каждая цифра в кадре указывает, откуда она. Пустой период — `no_data`,
публикации без охватов — `no_metrics`: отчёт из нулей читался бы как провал кампании.

```http
GET  /api/v1/media/recycle/candidates      → кандидаты по вовлечённости + все отказы с причинами
POST /api/v1/media/recycle                 {publication_id?, channel?, days, format, locale}
                                           → 201 ролик с origin; 409 no_candidates/below_threshold
POST /api/v1/media/reports                 {days, channel?, locale, format} → 201 отчёт + sources
POST /api/v1/media/reels                   {..., "locale":"en"} — язык в спеке и в таймингах
```

Тесты: `tests/test_media_recycle.py` — 34 проверки (ранжирование по вовлечённости, порог показов,
отказ без данных, происхождение в `spec_hash`, профили языков, `localize` с пересчётом таймингов и
отказом на переполнение, цифры отчёта против хранилища, API 201/409/422). Гейты: `media.recycle`,
`media.locale`, `media.report`. Демо — `scripts/demo_recycle.py`, результат —
`../20-DESIGN/video/backend/recycle-storyboard.png`, `recycle-en-storyboard.png`,
`report-storyboard.png`, `recycle.mp4` и `recycle-demo.json`.

## v3.20: кинематографичная озвучка (этап H)

Задача звучала как «сделать глубокую озвучку с бархатным баритоном и драматическими паузами».
Здесь важно, что именно из этого — **данные**, а что **код**.

**Провайдеры — реестр, а не ветки.** `media_voice.PROVIDERS` теперь содержит:

| Провайдер | Роль | Что даёт | Выразительность | Ударения |
| --- | --- | --- | --- | --- |
| `elevenlabs` | клиентский | Multilingual v2, stability/style, клонирование | 5 (максимум) | да |
| `steosvoice` | клиентский | русская фонетика и ударения в топонимах, speed/pitch | 4 | да |
| `yandex` | клиентский | SpeechKit: голос и скорость, без «выразительности» | 3 | нет |
| `local` | **self-hosted** | свой сервер Fish Speech / F5-TTS / Piper, 0 ₽ | 3 | да |
| `mock`, `file` | внутренние | тесты, демо, готовая озвучка диктором | — | — |

Три вещи, которые решены явно:

* **Self-hosted отдельно.** «Бесплатная озвучка на своём ПК» — не обещание клиенту сервиса.
  `available()` возвращает `providers` (клиентские + внутренние) и `self_hosted` отдельным
  списком; локальный движок работает по `MEDIA_LOCAL_TTS_URL`, цены и лимитов знаков у него нет.
* **Без ключа — отказ с именем переменной.** `synthesize(provider="elevenlabs")` без
  `ELEVENLABS_API_KEY` отвечает, чего не хватает, а не тишиной. Отдельная тонкость: id голоса —
  это id из библиотеки, а `Adam`/`George`/`Callum` — только названия; запрос с названием
  отвергается с подсказкой, потому что иначе провайдер молча озвучил бы «чужим» голосом.
* **Настройки, которых у провайдера нет, видны, а не исчезают.** У SpeechKit нет stability/style:
  `settings_for("yandex", ...)` возвращает их в `skipped`, а не делает вид, что применил.

**Подача — профиль, а не промпт.** `media_voice.PERFORMANCES`:

| Подача | Паузы | Темп | stability | style |
| --- | --- | --- | --- | --- |
| `neutral` (дефолт) | ×1,0 | 1,00 | 50 % | 0 % |
| `cinematic-baritone` | ×1,45 | 0,95 | **40 %** | **20 %** |
| `documentary` | ×1,2 | 0,90 | 55 % | 15 % |
| `energetic` | ×0,85 | 1,08 | 35 % | 35 % |

Значения баритона — из практики сторителлинг-каналов: стабильность 35–45 % (выше 70 % голос
становится монотонным), выразительность 15–25 %. И главное: **паузы — это время в кадре**.
`media_reel.build_reel_spec(..., performance="cinematic-baritone")` добавляет к каждой сцене
длительность пауз по пунктуации (тире, многоточие, конец фразы; запятая паузой не считается) и
масштабирует переходы — ролик становится длиннее на 10–15 %, и это видно в `duration`, а не
только слышно.

**Ударения.** Метка `+` перед гласной (`Дагест+ана`) уходит в синтез только тем движкам, которые
её понимают (ElevenLabs по принятой конвенции, SteosVoice штатно, локальные модели — да);
SpeechKit получает чистый текст, иначе произнесёт «плюс». В кадр, субтитры и `screen_text` метка
не попадает никогда — это проверено тестом и гейтом.

```http
GET  /api/v1/media/voice      провайдеры, цены, подачи, модели, self_hosted отдельно
POST /api/v1/media/reels      {"post":…, "performance":"cinematic-baritone",
                               "voice":{"provider":"elevenlabs","voice":"<voice_id>",
                                        "stability":0.4,"style":0.2,
                                        "stress":{"Дагестана":"Дагест+ана"}}}
```

Тесты: `tests/test_media_voice_performance.py` — 36 проверок (реестр и цены, выразительность как
данные, self-hosted отдельно от клиентских, паузы по пунктуации и их влияние на длительность,
пропущенные настройки, отказ на неизвестную подачу, ударения у провайдеров с поддержкой и без,
честные отказы ElevenLabs/SteosVoice/локального сервера, форма запроса к ElevenLabs, обе формы
ответа SteosVoice, API 201/422). Гейты: `media.voice_providers`, `media.performance`.

## v3.21: редакционные статьи (этап I)

Запрос: «AI сама продумывает структуру, текст органично дополняется изображениями,
инфографикой, схемами, графиками, таблицами и видео, каждая статья — собственная визуальная
композиция, результат — готовая редакционная публикация без ручной работы». Решение —
`10-ARCHITECTURE/adr/0024-article-engine.md`, продуктовая часть — `00-STRATEGY/13-article-engine.md`.

**Статья — спека `article.spec.v1`, HTML собирает код.** Модель пишет текст разделов; выбор
визуала, вёрстка, проверки и публикация — детерминированная часть. Поэтому вёрстка одинакова у
всех статей, а правка дизайна не требует перегенерации.

**Реестр блоков закрыт: 16 типов, 8 визуальных.** `table`, `chart`, `diagram`, `image`,
`gallery`, `comparison`, `stat`, `video` — у каждого визуала обязательны `alt` и `reason`, у
цифровых блоков — `source`.

Правила выбора визуала — данные (`VISUAL_RULES`), а не ветки под нишу:

| Правило | Данные раздела | Блок | Почему читателю так лучше |
| --- | --- | --- | --- |
| `prices` | `rows` (+`columns`) | `table` | варианты сравниваются в одной таблице, а не в абзаце |
| `trend` | `material` (числовой ряд) | `chart` | динамика видна в одну секунду (для столбцов причина другая — «разницу в одну секунду») |
| `process` | `steps` (≥ 2) | `diagram` | шаги не нужно держать в голове |
| `compare` | «сравн», «плюсы», «минусы» | `comparison` | разница без воды |
| `proof` | «исследование», «данные», «отчёт» | `stat` | цифра из источника показана, а не спрятана |
| `show` | `image_prompt`, «как выглядит» | `image` | иллюстрация объясняет быстрее текста |

Два правила, без которых схема разваливается:

* **данные раздела сильнее слов в тексте** — раздел со строками таблицы получает таблицу, даже
  если в тексте мелькнуло «отчёт» (слово тянет правило `proof` → плашку с цифрой);
* **невыполнимое правило не срабатывает** — `table` и `diagram` помечены `strict_data`: без
  строк и шагов они не выбираются вовсе, а не исчезают после выбора. Если данных под выбранный
  блок не нашлось, движок идёт по следующему кандидату.

**Проверки — данные, а не «человек посмотрел».** `check()` возвращает коды: `alt_missing`,
`reason_missing`, `source_missing`, `prop_required`, `block_unknown`, `heading_jump`, `too_short`,
`placeholder`, `too_few_words`/`too_many_words`, `keyword_not_in_title`, `no_visuals`,
`seo_missing`/`seo_too_long`, `keywords_missing`, `spec_version`. Уникальность — шинглы по 5 слов
против корпуса, порог `0.35`. `publish()` идемпотентен по `spec_hash`: `ready` ставится только
при пустых замечаниях, иначе `draft` с замечаниями внутри документа.

**HTML.** `render_html(spec)` — самостоятельная страница: типографика, инлайн-SVG для графика и
схемы, иллюстрация — SVG медиа-движка прямо в разметке (никаких внешних файлов и CDN), подписи с

## v3.22: пакеты правил и шаблоны публикации (этап I2)

Гибкость проверяется не обещанием, а тем, сколько стоит подключить новую нишу. В статьях это
две вещи — **политика темы** и **вёрстка**, и обе теперь данные.

**Пакет правил** (`RULE_PACKS`, файл `ARTICLE_RULE_PACKS`) добавляет правила «данные → блок»,
может отключать встроенные и задаёт политику публикации:

| Пакет | Что добавляет | Что меняется |
| --- | --- | --- |
| `default` | — | 350–4 000 слов, уникальность ≤ 0,35 |
| `high-stakes` (высокая цена ошибки: право, финансы, здоровье) | правило `risk` — врезка из данных раздела | оговорка отдельным блоком, минимум 500 слов, уникальность ≤ 0,20, `source` обязателен у сравнений, запрещены «гарантируем результат», «100% гарантия», «полностью безопасно» |

| Ключ политики | Что делает | Код замечания |
| --- | --- | --- |
| `min_words` / `max_words` | пороги объёма темы | `too_few_words` / `too_many_words` |
| `max_duplicate_ratio` | порог для `uniqueness()` | — (виден как `limit`) |
| `required_blocks` | блоки, без которых статья не готова | `block_required` |
| `require_sources` | у каких типов обязателен `source` | `source_missing` |
| `banned_phrases` | обещания, которые нельзя публиковать | `banned_phrase` |
| `disclaimer` | текст оговорки отдельным блоком | `block_required` |

**Шаблон публикации** (`TEMPLATES`, файл `ARTICLE_TEMPLATES`) — токены вёрстки, а не второй
рендерер: `accent`, `bg`, `fg`, `dim`, `line`, `font`, `max_width`, `radius`, `table_head`,
`stat_*`, `callout_*`. Акцент доезжает до inline-SVG графика и схемы — иначе «тёмный» шаблон давал
бы фиолетовый график.

| Шаблон | Для чего | Акцент | Гарнитура | Ширина |
| --- | --- | --- | --- | --- |
| `editorial` | новости и разборы | `#7c5cff` | системная sans | 760 px |
| `longread` | чтение 8–15 минут | `#0f766e` | антиква (Georgia) | 720 px |

Три решения, которые держат схему честной:

* **политика едет в спеке** (`spec.policy`): `check()` и `uniqueness()` читают пороги из статьи,
  поэтому строгая статья остаётся строгой при повторной проверке;
* **неизвестный пакет/шаблон — 422** (`pack_unknown` / `template_unknown`) со списком реестра:
  молчаливая подмена политики хуже отказа;
* **неприменимое правило не применяется**: правило пака с блоком не из реестра отбрасывается и
  видно в `invalid_rules` витрины, а не падает в рантайме.

По ходу этапа исправлены три дырки движка (подробно в ADR 0024, уроки 5–7): график и цифра больше
не берут «первый попавшийся материал» (`next(iter(numbers))`), у таблицы убран дефолт
`«данные клиента»` вместо источника, а сравнение выбирается по данным (`columns` из объектов), не
по слову «сравнить».

```http
GET  /api/v1/articles/packs            паки, шаблоны, ключи политики, имена переменных
POST /api/v1/articles                  {"topic":…, "rule_pack":"high-stakes",
                                        "template":"longread", "outline":[…], "materials":[…]}
GET  /api/v1/articles/{id}.html        готовая страница в выбранном шаблоне
```

Демо: `scripts/demo_article_packs.py` → `20-DESIGN/articles/backend/demo-article-default.html`
(545 слов, 4 визуала, `editorial`) и `demo-article-strict.html` (573 слова, 4 визуала, 2 врезки,
`longread`, оговорка пака), `demo-article-packs.png` — сравнение паков в одном кадре,
`*.spec.json` — спеки.

Тесты: `tests/test_article_packs.py` — 15 проверок (реестр и витрина, пак из файла, отключение
правил, неприменимое правило, политика в спеке и в `check()`, порог уникальности из пака,
оговорка отдельным блоком, врезка по данным раздела, токены шаблона и подстановка недостающих,
API паков и 422 на неизвестный код). Гейт: `article.packs`.

## v3.27: одна статья — четыре языка (этап I7)

Мультиязычный сайт из одной спеки — не «прогнать статью через переводчик». Три решения:

| Решение | Почему так |
| --- | --- |
| тексты приходят `translations`, движок их не сочиняет | перевод можно проверить редактором и сохранить; машинный перевод без проверки — не локализация |
| «хром» переводит код | «Read next», «source», «min read», `lang` и время чтения одинаковы во всех статьях языка |
| лимиты под язык: заголовок 70 у ru и 60 у en | английский заголовок обрезается в выдаче раньше |
| свой темп чтения статьи: 180/220/160/170 слов/мин | темп титров ролика (2.6 слова/с) даёт 8 минут вместо 5 |
| объём пересчитывается по переведённому тексту | иначе английская версия показывает русское «390 слов» |
| перевод — отдельная статья (`id`, слаг `…-en`) | иначе публикация перезаписывает русскую версию |
| `hreflang` полон: свой язык + `x-default` | без ссылки на себя переводы конкурируют друг с другом |
| непереведённое называется | `missing` с адресом поля, `complete: false`, строгий режим — отказ `translation_missing` |

```http
GET  /api/v1/articles/locales                     # темп чтения, лимиты, подписи
POST /api/v1/articles/{id}/translations            {"locale": "en", "translations": {…}, "urls": {…}}
GET  /api/v1/articles/{id}/translations            # переводы + группа hreflang
```

Частичная версия — законный черновик и не публикация: полстраницы по-русски на английской версии
хуже, чем её отсутствие.

Демо (`scripts/demo_article_i18n.py`): `20-DESIGN/articles/backend/demo-article-i18n-ru.html` и
`demo-article-i18n-en.html` — две версии с тремя `alternate` в `<head>`; `demo-article-i18n-report.html`
— группа `hreflang`, темпы по языкам и честная неполнота казахской версии (17 полей без перевода,
отказ в строгом режиме); `demo-article-i18n.json` — машинный отчёт.

Тесты: `tests/test_article_i18n.py` — 13 проверок (реестр языков и подписей, темп статьи против
темпа титров, полный перевод и переключение «хрома», `missing` с адресом поля, строгий отказ и
черновик, `locale_unknown` вместо тихого отката, `already_localized`, лимит заголовка под язык,
`hreflang` с self и `x-default`, `hreflang_self_missing`/`hreflang_default_missing`, разметка
`alternate`, матрица языков, API-поток и неизвестный язык). Гейт: `article.i18n`.

## v3.26: A/B заголовка и вводки на одном теле статьи (этап I6)

Заголовок решают данные, а не вкус редактора — но только если сравнивать честно. Четыре правила
и один запрет:

| Правило | Как проверяется |
| --- | --- |
| **тело статьи одно** | у теста есть `body_hash` по всем блокам, кроме вводки; если тело изменилось после старта — `body_changed` |
| **варианты проходят правила** | длина ≤ 70 знаков, ключевое слово на месте, без запрещённых паком обещаний; годных меньше двух — `no_variants` |
| **разбиение стабильное** | корзина из `sha256(test_id + visitor)`: один читатель всегда видит один вариант |
| **решение по статистике** | двухвыборочный z-тест для долей; мало показов — `not_enough_data` с числом, `p > α` — `no_difference` |
| **запрет** | в реестре формул нет «прогноза CTR»: есть гипотеза, что именно проверяем |

```http
POST /api/v1/articles/{id}/abtests                      {"count": 3}
POST /api/v1/articles/abtests/{test}/assign?visitor=…    # стабильный вариант для читателя
POST /api/v1/articles/abtests/{test}/metrics             {"code": "number", "impressions": 1000, "clicks": 78}
POST /api/v1/articles/abtests/{test}/evaluate            # решение: победитель или честный отказ
POST /api/v1/articles/abtests/{test}/apply               # только заголовок и вводка, версия +1
```

`HEADLINE_KINDS` (вопрос, число, инструкция, выгода) и `LEAD_KINDS` (полная вводка, первое
предложение, «коротко: структура») — реестр формул с гипотезами у каждой. Число в заголовке
берётся из структуры статьи и склоняется: `plural()` даёт «3 вещи» и «5 вещей», потому что
«5 вещи» — не A/B, а опечатка. `salt` в теле запроса позволяет запустить второй тест на той же
статье, не превращая ретрай в дубль.

Демо (`scripts/demo_article_ab.py`): три варианта на одном теле, 3 000 читателей.
`20-DESIGN/articles/backend/demo-article-abtest-report.html` — карточки вариантов с гипотезами,
столбцы CTR, z-тест и честный отказ второго теста; `demo-article-abtest-applied.html` — статья
с заголовком победителя; `demo-article-abtest.json` — машинный отчёт (тело, метрики, решение,
`body_unchanged: true`).

Тесты: `tests/test_article_ab.py` — 18 проверок (варианты на одном теле, `title_too_long`,
`keyword_lost`, `banned_phrase`, `no_variants`, стабильность и покрытие разбиения, суммирование
и валидация метрик, `not_enough_data`, победитель, шум, известный случай z-теста, `no_winner`,
применение без изменения тела, `body_changed`, `already_applied`, API-поток и ранняя остановка).
Гейт: `article.abtests`.

## v3.25: перелинковка по смыслу и обновление вечнозелёных статей (этап I5)

Блог состоит не из статей, а из связей между ними. Две вещи, которые делаются «на глаз» и потому
не делаются вовсе: ссылки «Читайте также» и обновление старых материалов.

### Ссылки: близость вместо тегов

| Решение | Почему так |
| --- | --- |
| свой локальный вектор: мешок основ слов + биграммы, `1+log(tf)`, L2, 512 измерений | детерминированный, без сети и токенов; близость воспроизводима в тесте |
| окончания срезаются, служебные слова выбрасываются | иначе «как», «что», «для» делают похожими любые две статьи |
| **не** `llm._hash_embed` | вектор там — хэш всего текста: у статей об одном косинус 0.033, о разном — 0.031. Перелинковка на нём была бы шумом, и это зафиксировано тестом |
| порог и лимит — `ARTICLE_LINK_MIN_SCORE` / `ARTICLE_MAX_LINKS` | ниже порога ссылка не ставится, отказ называется (`no_candidates`) с числом |
| анкор — заголовок статьи, блок `related` — перед призывом | «читать далее» не объясняет, куда ведёт ссылка (`link_anchor_missing`) |
| причина и история у блока | ссылка — редакционное решение; `history` объясняет, когда и почему она появилась |

```http
GET  /api/v1/articles/{id}/links          # кандидаты: слаг, анкор, близость, порог
POST /api/v1/articles/{id}/links          # поставить блок «Читайте также» (409 already_linked)
```

### Обновление: только по источникам

«Вечнозелёная» статья стареет цифрами, а не текстом, поэтому `refresh()` не перегенерирует статью:

* меняются только `chart`/`table`/`stat`, у которых есть источник и ряд в присланных материалах
  (ряд ищется по `props.material`, затем по `source` блока);
* нет материала — число остаётся прежним и попадает в `skipped` с кодом `material_missing`:
  догадка в таблице цен хуже устаревшей цифры;
* нет изменений — `no_changes`, версия не растёт: «обновлено» без правки — это галка;
* просрочка считается от `reviewed_at` и срока `ARTICLE_REVIEW_DAYS`; статья без метки
  `evergreen` видна в отчёте отдельно — срок ей не назначен.

```http
GET  /api/v1/articles/evergreen           # что пора обновлять (now можно передать)
POST /api/v1/articles/{id}/refresh        # материалы → версия 2, changes и skipped
```

Плюс авто-`canonical`: адрес статьи собирается из `ARTICLE_CANONICAL_BASE` и слага, если домен
платформы известен. Без переменной canonical нет вовсе — ссылка «на всякий случай» склеивает
выдачу вместо того, чтобы её разделять.

Демо (`scripts/demo_article_links.py`): блог из четырёх статей, собранных движком.
`20-DESIGN/articles/backend/demo-article-links.html` — статья об охватах с двумя ссылками по
смыслу (0.67 и 0.53) и `rel=canonical`; `demo-article-refresh.html` — та же статья после
обновления по прайсу (3 900 → 4 400 ₽, ряд переходов остался прежним), версия 2;
`demo-article-links-report.json` — близость «одна тема / другая тема», отказ `no_candidates`
у статьи о ценах (0.078 при пороге 0.14), `skipped`, отчёт по вечнозелёным.

Тесты: `tests/test_article_links.py` — 24 проверки (близость против случайной, игнор регистра и
служебных слов, ранжирование кандидатов, пустой индекс, порог, лимит из окружения, отсутствие
дублей, блок перед призывом с историей, разметка с анкорами, `link_broken`/`link_self`/
`link_anchor_missing`/`link_duplicate`/`related_empty`, метка `evergreen`, просрочка, обновление
только по источнику, сохранение числа без материала, `no_changes`, `fresh`, отчёт, API ссылок и
обновления, авто-`canonical`). Гейт: `article.links`.

## v3.24: иллюстрации провайдером — лицензия и кэш (этап I4)

Схема, график и таблица отвечают на вопрос «сколько». Фотоподобная сцена отвечает на «как это
выглядит». Второе нельзя рисовать кодом, поэтому статья научилась брать файл у провайдера — но
так, чтобы это было не «подключили API», а «статья не публикуется без прав».

| Провайдер | Что нужно | Что получается |
| --- | --- | --- |
| `brand-card` | ничего | своя графика медиа-движка (inline-SVG), лицензия `own` |
| `ai-generate` | `MEDIA_IMAGE_PROVIDER_KEY`, `MEDIA_IMAGE_PROVIDER_URL` | файл от генератора + лицензия из ответа |
| `stock` | `MEDIA_STOCK_KEY`, `MEDIA_STOCK_URL` | фото банка + лицензия с `terms_url` |

Доступность считается **из окружения** и видна целиком: `available`, `needs` (какие именно
переменные), `reason`. `GET /api/v1/articles/images` отдаёт витрину, кэш и последние
иллюстрации — клиент не гадает, почему картинка «нарисовалась сама».

```http
GET /api/v1/articles/images
{
  "providers": [{"code": "ai-generate", "available": false,
                 "needs": ["MEDIA_IMAGE_PROVIDER_KEY", "MEDIA_IMAGE_PROVIDER_URL"],
                 "reason": "нужны переменные: …"}],
  "cache": {"entries": 0, "providers": {}, "cost_rub": 0.0}
}
POST /api/v1/articles  {"topic": …, "image_provider": "ai-generate", "outline": […]}
```

Пять правил, каждое — тестом и гейтом `article.images`:

* **без лицензии — нет иллюстрации.** Ответ провайдера без `license.name`/`license.type`
  отвергается кодом `license_missing` ещё до сборки блока. Проверка стоит в `generate_image`,
  а не только в HTTP-обёртке: подменённый или забывчивый провайдер не проведёт чужой файл;
* **подпись видна читателю.** В HTML — `<figure><img alt … loading="lazy">` и
  `figcaption` с `attribution()` («Generated by ExampleAI · провайдер: ai-generate»).
  Пакет правил может требовать подпись (`require_attribution`) — тогда иллюстрация без имени
  лицензии даёт `attribution_missing`;
* **одинаковый запрос не оплачивается дважды.** Ключ кэша — `sha256(provider + prompt + size)`,
  запись в `Collection("article_images")` хранит `url`, размеры, лицензию, `cost_rub` и
  `retrieved_at`. Повтор возвращает `cached: true`; `image_cache_stats()` показывает траты;
* **нет ключа — нет молчаливой подмены.** Статья выходит со своей графикой, но в спеке
  остаётся `provider: brand-card`, `requested_provider: ai-generate` и `fallback_reason` с
  именами переменных: читатель видит карточку, редактор — причину;
* **неизвестный провайдер отвергается в плане** (`image_provider_unknown`) — до траты денег.

Демо (`scripts/demo_article_images.py`, сеть не нужна — провайдер эмулируется счётчиком
вызовов): `20-DESIGN/articles/backend/demo-article-images-fallback.html` — статья без ключа
со своей графикой и причиной; `demo-article-images-licensed.html` — внешний файл с лицензией
и подписью; `demo-article-images-report.json` — отказы, лицензия, кэш (`entries`, `cost_rub`,
`provider_calls: 1` на два одинаковых промпта), `license_missing` на ответ без прав.

## v3.23: галерея и видео в статье (этап I3)

Статья перестала быть «текст плюс таблица»: два блока берут визуал из медиа-движка, а не из
заглушки.

| Блок | Данные раздела | Что получается | В HTML |
| --- | --- | --- | --- |
| `gallery` | `gallery: [{title, caption, alt}]`, минимум 2 | карточка по спеке на каждую плитку (`media.build_spec`, 1:1) | сетка inline-SVG, у каждой плитки своя подпись и `alt` |
| `video` | `video: {items, note, cta}` или `video: {src}` | `reel.spec.v2` из заголовка раздела и пунктов (`media_reel.build_reel_spec`, 16:9, 25 fps) | полоса сцен с временем и подписями; `<video controls>` при ссылке клиента |

Что решено явно:

* **кадры ролика не вставляются в статью** — в разметке полоса сцен, а спека ролика полная и
  пригодна для рендера в MP4 (`media_reel.submit`);
* **лимиты проверяются**: `video_too_long` сверяет длительность и число сцен с
  `media_reel.limits()`, которые читаются из окружения;
* **нет ни спеки, ни ссылки — нет блока** (`video_source`); ссылка клиента — законный путь,
  своего файла мы не выдумываем;
* **один элемент — не галерея**: одна плитка превращается в `image`;
* **у каждой плитки свой `alt`**: проверка ловит `blocks[i].items[j].alt`, а не блок целиком;
* **реестр `VIDEOS`** (`reel` — внутренний, `external` — ссылка клиента) виден в
  `GET /api/v1/articles/summary` наравне с `IMAGES`.

```http
POST /api/v1/articles   {"topic":…, "outline":[{"heading":"Примеры оформления",
                          "gallery":[{"title":"Карточка 1:1","caption":…,"alt":…}],
                          "text":…},
                         {"heading":"Как выглядит ролик",
                          "video":{"items":[…],"note":…,"cta":…},"text":…}]}
```

Демо: `scripts/demo_article_media.py` → `20-DESIGN/articles/backend/demo-article-media.html`
(454 слова, 4 визуала, 4 inline-SVG), `demo-article-media.spec.json` (внутри — полная
`reel.spec.v2`), `demo-article-media-report.json` (сториборд, лимиты, проверки),
`demo-article-media-reel-frame.png` — кадр ролика, собранный из этой же спеки. Ролик демо:
3 сцены, 10,73 с, 16:9, 25 fps при лимите 60 с — хук, пункты, финал с призывом.

Тесты: `tests/test_article_media.py` — 13 проверок (плитки и их `alt`, порог в две плитки,
`alt_missing` с путём до элемента, inline-SVG без внешних файлов, спека ролика и её валидность,

## v3.5: Go-Live Readiness — что стало боевым

Раздел отвечает на вопросы аудита «можно ли включать платежи и живые аккаунты».
Каждый пункт проверяется тестом, а не описанием.

### 1. `platform:admin` вынесен из `owner`

* `users.is_platform_admin` (миграция `0003_golive`), права `platform:admin|impersonate|ops`
  не выдаются ни одной роли воркспейса: `rbac.ROLE_PERMISSIONS["owner"]` = `PERMISSIONS − PLATFORM_PERMISSIONS`.
* Зависимость `rbac.require_platform_admin(permission)` → `403` c `detail.type="forbidden"`,
  `role` и подсказкой. Флаг читается из claim `platform_admin` в JWT (`auth.sessions.issue`)
  или из `X-Platform-Admin` — **только** в демо-режиме.
* `/me` отдаёт `is_platform_admin` и `source`, чтобы UI не показывал платформенные кнопки владельцу.
* Тесты: `test_golive_api.py` (owner → 403, header/JWT с флагом → 200, `/impersonate` под `platform:impersonate`).

### 2. Реальный LLM и pgvector/RAG

* `llm.py` — OpenAI-совместимый роутер: роли → модели (`heavy`/`fast`/`vision`/`premium`),
  цены в рублях, учёт токенов (`llm.cost_report()`), ретраи на 429/5xx, таймауты,
  JSON-режим, эмбеддинги 1024.
* `knowledge.py` — Brand Brain: источники → карточки → чанки 300–600 символов → эмбеддинги;
  гибридный поиск **BM25 + косинус**, объединение через Reciprocal Rank Fusion, цитаты `card_id`.
* `generator.py` — рой на реальных вызовах: strategist (RAG-бриф) → copywriter → adapter →
  fact-checker (JSON) → compliance (правила) → editor (порог 3,5, ≤2 итерации).
  Ответ содержит `llm.mode`, число вызовов и токенов, `rag.hits`.
* Без ключа/при `DRY_RUN=1` клиент работает в симуляции и **честно** помечает
  `simulated: true`; `/health` показывает `llm.mode=simulated`.
* Тесты: `test_golive_llm.py` (выбор модели, стоимость, ретраи, JSON, эмбеддинги, RAG, чанки),
  `test_golive_api.py` (`/knowledge/*`).

### 3. Остальные домены — в PostgreSQL

* Таблица `entity_docs` (`collection`, `id`, `workspace_id`, `payload jsonb`, `position`) —
  см. ADR 0014. Через `docs.Collection` в БД переведены: Bio, автоматизации, мониторинг, A/B,
  Brand Brain, Инбокс. `collection` совпадает с целевой таблицей, поэтому переход на
  типизированную схему — механический.
* `DATA_LAYER=db` → источник правды PostgreSQL, память как кэш; `memory` → демо.
* Тесты: `test_golive_llm.py::test_collection_persists_in_db_layer` (запись/чтение/удаление
  через «новый процесс»), `::test_collection_memory_mode_is_honest`.

### 4. Боевые адаптеры

* **VK**: двухшаговая загрузка фото (`photos.getWallUploadServer` → upload → `photos.saveWallPhoto`)

Обоснование — ADR 0016, стратегия — `00-STRATEGY/08-seo-content-strategy.md`.

## Эксплуатация: метрики, права Redis, резервные копии

Три вещи, которые проверяются релиз-гейтом (пункты `infra.observability`,
`infra.redis_acl`, `db.backup_restore`) и тестами, а не «описаны в документе».

### Метрики

```bash
curl -s localhost:8000/metrics | grep posiz_        # формат Prometheus
```

Все проверки сразу — `bash scripts/verify_all.sh` (быстрый набор → живые тесты → гейт →
openapi → сайт). Скрипт сам подставляет `DATABASE_URL`/`REDIS_URL` из `ORBITA_TEST_*` и
предупреждает, если живая инфраструктура не задана: «зелено без инфраструктуры» — это не
доказательство изоляции и бэкапа, и код возврата об этом говорит.

Очередь публикаций (`due_now`, `oldest_due_age_seconds`, `stale_leases`), доступность
Redis, режим LLM, счётчики процесса (отложенные по лимиту канала, превышения квоты,
маркеры инъекций в данных). В проде нужен `METRICS_TOKEN` — без него `/metrics` отвечает
403; `pg_stat_statements` включает `scripts/dev_stack.sh up`.

### Права Redis

API и воркер работают разными пользователями ACL (ADR 0022). Правила живут в одном файле
`scripts/redis_acl.sh` — его же вызывает CI, чтобы dev и CI не разъезжались:

```bash
export REDIS_API_PASSWORD=... REDIS_WORKER_PASSWORD=...   # выдаёт dev_stack.sh up / секрет-хранилище
export ORBITA_REDIS_ROLE=worker                            # для процесса воркера
```

```bash
bash scripts/redis_acl.sh     # идемпотентно: пересоздаёт права из паролей в env
```

У роли API есть `sess:*`, `user_sessions:*`, `state:*`, `auth:state:*`, `rl:*`, `chanrl:*`,
`arq:*` и нет доступа к `pub:*`; у воркера — наоборот. `FLUSHALL`, `CONFIG`, `ACL`,
`SHUTDOWN`, `MONITOR`, `DEBUG` запрещены обеим ролям.

### Резервные копии и проверка восстановления

```bash
# роль orbita_backup (BYPASSRLS CREATEDB) создаёт dev_stack.sh up
export BACKUP_DATABASE_URL="postgresql+psycopg://orbita_backup:...@127.0.0.1:5432/orbita"
bash scripts/verify_backup.sh
# → таблиц: 45/45, политик RLS: 89/89, ревизия: 0006_rls_strict
```

Почему отдельная роль: у таблиц `FORCE ROW LEVEL SECURITY`, и `pg_dump` под рабочей ролью
падает на политиках (`query would be affected by row-level security policy`). Скрипт делает
полный цикл (dump → временная база → restore → сверка таблиц, ревизии и числа политик) и
возвращает ненулевой код, если копия не восстанавливается.

## Как прогнать тесты на живой инфраструктуре

Половина дефектов схемы видна только на PostgreSQL (SQLite не проверяет типы, enum и RLS),
поэтому есть второй набор тестов и гейт с реальной базой:

```bash
# 1. PostgreSQL 17 + pgvector и Redis 8 без Docker (initdb, роль, база, расширения, миграции)
./scripts/dev_stack.sh up
eval "$(./scripts/dev_stack.sh env)"          # DATABASE_URL, REDIS_URL, ORBITA_TEST_*

# 2. Всё сразу: быстрый набор, живые тесты, гейт, openapi, сайт
bash scripts/verify_all.sh                   # ИТОГ: всё зелёное на целевой инфраструктуре

# 2а. По шагам — полный набор (643 теста) и гейт
PYTHONPATH=src pytest tests -q                # без инфраструктуры: 643 passed, 29 skipped
PYTHONPATH=src python -m orbita.release_gate  # 53/53 с живой инфраструктурой

# Или через Docker
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d
```

Без `ORBITA_TEST_PG_URL`/`ORBITA_TEST_REDIS_URL` интеграционные тесты помечаются `skip`
с причиной — «нечем проверить» отличается от «проверено и работает». В CI оба сервиса
поднимаются автоматически (`.github/workflows/ci.yml`).

## v3.9: второй аудит — схема, изоляция, публикация, маркировка

Второй аудит дал 4/10 и потребовал не добавлять возможностей, пока не закрыты пять пунктов:
schema+ORM, tenant/workspace, регистрация/membership/RLS, единый Publishing Engine и сквозная
генерация для произвольного пространства. Разбор по каждому утверждению —
`00-STRATEGY/09-audit-response.md` (часть II), решения — ADR 0019.

Главный вывод проверки: **SQLite-тесты были зелёными, а на PostgreSQL схема не поднималась.**
Отсюда три системных исправления: ORM объявлена источником истины по типам, контекст
арендатора ставится в каждой транзакции, а соответствие ORM↔SQL проверяет гейт, а не глаз.

| # | Что подтвердилось в аудите | Что сделано |
|---|---|---|
| 1 | `users.email citext` без `CREATE EXTENSION` | `sql/00_cluster_init.sql`: `citext` на уровне кластера; `String` в ORM заменён на `citext`, идентификаторы — `UuidStr`, токены — `CipherText(bytea)` |
| 2 | `publications.status` — `varchar` против enum в ORM, нет `retry_wait` | `Enum(publication_status)` + `retry_wait` в SQL-типе (миграция `0005`), иначе ретрай физически невозможен |

| 4 | RLS покрывал не все таблицы; `can_access_workspace()` рекурсивно обходил таблицы под RLS | политики для `workspaces`, `memberships`, `entity_docs`, `channel_accounts`; проверка через `app_workspace_id()` и `app.actor_role` |
| 5 | magic-link выдавал `owner` в `ws_de` | `accounts.register()`: tenant + личное пространство `ws_<hash10>` + членство `owner`; роль `owner` — только для своего пространства, иначе `editor` |

| 7 | `publish-now` публиковал мимо машины состояний | единственный путь — `workers.tasks.publish_publication` (аренда, backoff, журнал попыток, ответы 409/502) |

| 12 | рекламодатель в маркировке был захардкожен (`ООО «Договор Эксперт»`) | реквизиты берутся из профиля пространства; без них реклама блокируется (`ADVERTISER_MISSING`); `is_marked()` требует «Реклама» + рекламодателя + валидный erid |

### Что в этом аудите устарело или сформулировано неточно

* **«RLS нет вовсе»** — политики были, но неполные: `channel_accounts`, `inbox_events`,
  `entity_docs` оставались вне политик, а `can_access_workspace()` обходила таблицы под RLS.
  Формулировка «RLS не включён» неверна, «RLS покрывает не всё» — верна.
* **«Изоляция не реализована»** — в слое БД контекст и политики были; **не** было изоляции в
  слое памяти, которым пользуются тесты и демо. Именно это воспроизведено тестом и исправлено.
* **«Publishing Engine отсутствует»** — машина состояний, аренда и backoff существовали
  (ADR 0017); отсутствовали журнал попыток, сверка и продление аренды, а `publish-now` шёл
  в обход. Исправлено точечно, движок не переписывался.
* **«Тестов нет»** — 517 тестов, но согласны с аудитом в главном: тесты на SQLite не доказывают
  ни типов, ни RLS. Отсюда `orm.schema` в гейте и отдельный план тестов на реальном PostgreSQL.

## v3.8: разбор внешнего аудита — что подтвердилось и что исправлено
